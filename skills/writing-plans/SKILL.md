# Planes de implementación

Inspecciona el estado del proyecto y aclara solo decisiones que afecten alcance. Describe objetivo, comportamiento esperado, interfaces, archivos afectados y criterios de aceptación.

Divide en pasos ejecutables según dependencias; incluye validación relevante y recuperación para cambios de riesgo. No llenes el plan con todo el código por anticipado ni con pruebas que repitan la implementación.

Señala decisiones abiertas y restricciones comprobadas. Si el usuario autorizó implementación, continúa tras planificar. Un plan no es un resultado implementado.
